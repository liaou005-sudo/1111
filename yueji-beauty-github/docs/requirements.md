# 单门店综合美业微信小程序需求

## 已确认

- 一家综合美业门店，包含美容护肤、美甲美睫、美发、身体护理等分类。
- 首次登录自动成为普通会员，余额与积分初始化为零。
- 免费预约，到店结算，不收预约定金。
- 必须有预约、会员、积分、储值、活动展示、项目价格和基础门店信息。
- 目标为正式上线微信小程序；先完成了网页原型。用户尚未注册小程序账号。

## 顾客端

首页、项目列表与详情、预约填写、我的预约、会员中心、储值充值与明细、积分明细与兑换、优惠券、活动详情、门店地址/营业时间/客服。底部导航：首页、项目、预约、我的。

## 业务流程

1. 顾客登录，服务端识别微信身份并创建或读取会员账户。
2. 选择项目、适用服务人员、日期与空闲时段。
3. 服务端根据项目时长、员工排班和已有预约原子校验并创建预约，避免重复占用。
4. 顾客到店完成服务，店家确认金额和付款方式。
5. 店家核销后记录消费流水；储值付款扣减余额，按有效消费金额发放积分。
6. 退款根据原交易逆向处理余额、赠送金及积分，保留审计记录。

## 演示规则，尚需门店确认

- 每消费满 1 元获得 1 积分，充值不赠积分。
- 充值 500 赠 30，充值 1000 赠 100。
- 200 积分兑换满 198 可用的 20 元护理券；500 积分兑换满 398 可用的 50 元护理券。
- 以上价格、赠送、兑换条件、营业时间和项目均为原型样例，并非确定经营规则。
- 需确认取消期限、爽约处理、积分有效期、赠送金消费顺序、退款规则和优惠叠加规则。

## 店家后台待开发

- 项目分类、价格、时长、图片与上下架。
- 服务人员、技能绑定、工作时段、休息时间与排班。
- 预约查询、调整、取消、到店确认与服务核销。
- 会员查询、储值和积分流水、退款及操作审计。
- 活动与优惠券配置、核销。
- 门店信息、角色权限与客服配置。

## 后端待开发

微信身份认证、会员账户、预约事务、服务器时区与排班计算、账户权限、账务和积分不可重复入账、支付回调验签与幂等、退款、持久化数据库、管理端认证、备份和恢复。金额应使用整数分，敏感密钥只在服务端配置。顾客不能自行修改余额或确认消费。

## 上线准备

注册门店主体小程序账号并获取 AppID；后续根据微信平台当时要求配置认证、服务类目、支付商户、隐私说明和相关上线资料。在开发者工具中联调并完成真机及支付测试，再提交审核。具体平台规则应在实施时查询官方文档。

## 当前代码的边界

所有原型交互是本地内存演示。页面中的“首次登录”展示不代表已经接入微信认证。“模拟消费积分”仅为测试兑换界面。客服和地图入口不会调用真实服务。
